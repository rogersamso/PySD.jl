Writing and building models

PySD.@equations — Macro
@equations [name] begin
    @parameters begin
        τ = 10, [unit = u"minute", description = "Characteristic time"]
    end
    @variables begin
        temperature(t), [unit = u"°F"]
    end
    ∂t(temperature) ~ -(temperature - room_temperature) / τ
    temperature(t₀) ~ 180
end

A set of equations with the declarations of their names. @parameters are given values, @variables have an equation (x(t) when they change with time); each declaration carries [unit = …] and optionally description, nonnegative, input, output. Equations use ~. With a name, the set is a component. Model builds a model from one or more sets.

source
PySD.EquationSet — Type
EquationSet

What @equations returns: declarations, equations and the Julia values they use. A set with a name is a component; its names get the name as a prefix (retailer.inventory). defined_in is the module the set is written in: a model built from it keeps its compiled code there (so that a package can precompile it).

source
PySD.Model — Type
Model(sets…; time, time_unit, saveat = step(time), inputs = (;))

Build a model from equation sets (views, components, connections): join them, check the declarations, units, dimensions and equations, sort the equations and generate the code that runs it. time = t₀:Δt:t_final; inputs are the input sheets, by name. numerics = :python keeps Python PySD's last digits (for translated models: the C maths library, numpy's order of additions, LAPACK's gesv); the default, :julia, uses Julia's own functions.

source
PySD.StatefulOperator — Type
StatefulOperator

What smooth, delay, trend, sample_if_true and the fixed delay x(t - τ) implement: how many hidden stocks they have, their initial values, their rates of change and the operator's value. Model creates the hidden stocks. A new operator is a new subtype with these methods:

nstates(op)
initial_states(op, x, args...; init)
rates!(d, op, s, x, args...)
output(op, s, x, args...)

(s are the hidden stocks, x the input, args the other arguments).

source
PySD.check_units — Function
check_units(model)

The equations of model whose units don't add up, as a vector of issues (file, line, variable, what differs); empty when they all do. Same unit for +, -, min, max, comparisons and the branches of ifelse (units of one kind but another size, EJ and TJ, need a conversion factor); *, / and ^ combine units; exp, log and trigonometric functions take NoUnits; ∂t(x) has the unit of x per unit of time; the delay times of smooth, delay and x(t - τ) are times. run_model(model; check_units = true) checks before running (:warn to run anyway).

Inputs: Excel, lookups, other models

These are written inside @equations, where they are found without being imported.

PySD.ExcelSheet — Type
excel(path, sheet)

An Excel sheet, given to Model by name in inputs and read in @parameters with constant, lookup and data. A different scenario is a different sheet given to the run: run_model(m; inputs = (; scen = excel(…))).

source
PySD.constant — Function
constant(sheet, cells; transpose = false)

A number or an array from a cell, a range or a named range (Vensim's GET DIRECT CONSTANTS; transpose = true for its *). The declaration gives it its dimensions: rows are the first, columns the second.

source
PySD.lookup — Function
lookup(sheet, x, cells)

A lookup read from Excel (Vensim's GET DIRECT LOOKUPS): x are the cells of the x values (a named range, or a row number or column letter), cells those of the y values; called as f(x). With dimensions, one series per element: f(x) is an array, and with an array x the dimensions line up by name. It is read when its declaration gives it its dimensions.

source
PySD.data — Function
data(sheet, time, cells; method = :interpolate)

A data series read from Excel (Vensim's GET DIRECT DATA), called with time, d(t). method is Vensim's keyword: :interpolate, :hold_backward, :look_forward or :raw.

source
data(parents, name)

A data series from outside the model (Vensim's data variables without an equation): parents is an input given to Model and to the run, a tuple of sources, and name the series' name; the first source that has it gives it. A source is a run of another model (run_model(world)) or a file of series (series_file). Called with time, d(t), it interpolates linearly between the source's times; with dimensions, they line up by name.

source
PySD.series_file — Function
series_file(path)

Data series read from a .csv or .tab file, as Python PySD's data_files: the times in the first column and a column per series (or the times in the first row and a row per series), named as in Vensim, Temperature change or GDP[EU], Real demand[agriculture, EU] for the elements of an array. A source of data: names and elements match the model's as the translation writes them (lower case, other characters as _).

source
PySD.piecewise_linear — Function
piecewise_linear(x₁ => y₁, x₂ => y₂, …)

A lookup: called as f(x), it interpolates linearly between the points and keeps the first or last value outside them, as Vensim.

Arrays

PySD.sum_over — Function
sum_over(x, d)
sum_over(x, (d1, d2, …))

The sum over dimension d, or over several at once, which the result no longer has (Vensim's SUM(x[d!]), SUM(x[d1!, d2!]); Julia's sum(x; dims = d) keeps d with length 1). maximum_over, minimum_over and prod_over likewise.

source
PySD.previous — Function
previous(x, d)

Each element takes the value of the one before it along dimension d; the first takes zero.

Running and results

PySD.run_model — Function
run_model(model; params = (;), inputs = (;), check_units = false)

Run model from t₀ to tfinal with Euler steps of Δt, as Vensim, and save every saveat. params changes parameters by name ((; τ = 5)), inputs input sheets (`(; scenw = excel(…))).checkunits = truechecks the units first ([checkunits](@ref)) and stops if they don't add up;:warn` prints the issues and runs anyway.

source
run_model(model, solver; params = (;), inputs = (;), check_units = false, kwargs...)

Run model with a SciML ODE solver instead of Vensim's Euler steps, and save every saveat, as run_model(model). kwargs go to solve (dt is Δt unless given, abstol, reltol, …).

Euler() with steps of Δt gives Vensim's values. Fixed delays and sample_if_true move only at the model's ticks, every Δt, whatever the solver: it stops at each, and its own steps in between integrate the stocks.

source
PySD.Results — Type
Results

What run_model returns: res.time, and the values of every name by name, res[:temperature] (a vector over the saved times; parameters and constants give their value).

source
SciMLBase.ODEProblem — Method
ODEProblem(model; params = (;), inputs = (;), kwargs...)

The model as a SciML ODEProblem from t₀ to tfinal, with the given parameters and input sheets (as `runmodel's). Solve it with any ODE solver (Euler()withdt = Δtis Vensim's);Results(model, sol)gives the values of every name from the solution.kwargsgo toODEProblem`.

A model with fixed delays, sample_if_true or switches on the time (t ≥ 2015, a pulse) gets a callback that stops the solver at every step of Δt (the model's ticks), where they move or switch, as Vensim's. With another solver than Euler() with dt = Δt, equations written for steps of Δt (that use Δt as a value, test the time for equality, or keep a stock non-negative) are named in a warning: those are the ones that may mean something else.

Precompiling a model

PySD.@precompile_model — Macro
@precompile_model name = expr

In a package: const name = expr, a Model, built and run once while Julia precompiles the package, so that the package saves the model with all that building and running it compiled. Later sessions load it ready to run: using MyModel; run_model(MyModel.name).

module MyModel
using PySD
@precompile_model model = include("../mymodel.jl")
end

Julia precompiles the package again when one of its files, or an Excel sheet the model reads, changes.

The equations as LaTeX

PySD.pysd_export_latex — Function
pysd_export_latex(sys; filename=nothing)

Render a ModelingToolkit ODESystem as LaTeX equations.

If filename is given the LaTeX string is written to that file (wrapped in a minimal document preamble so it can be compiled standalone). The raw LaTeX string is always returned.

Example

include("my_model.jl")          # defines `sys`
pysd_export_latex(sys)                         # returns LaTeX string
pysd_export_latex(sys; filename="eqs.tex")     # also writes to file
source
pysd_export_latex(m::Model; filename = nothing)

The equations of a model written with @equations, as LaTeX, the way they are written: a section per set of equations (a view of a translated model), with its equations (∂t(x) as dx/dt, sum_over as Σ, ifelse as cases, selections as x[a]) and a table of its names, units and descriptions. Needs Latexify.jl (using Latexify). With filename, it also writes a document that compiles on its own.

using PySD, Latexify
m = include("model_dsl/model.jl")
pysd_export_latex(m; filename = "model.tex")

Helpers for translated ODE and MTK models

Models translated with PySD's older backends (backend="ode" or "mtk") are plain Julia ODE functions or ModelingToolkit systems that call these helpers. Models written with @equations, or translated with backend="dsl", don't need them.

PySD.pysd_vector_select — Function
pysd_vector_select(sel, expr, missing_vals, numerical_action, error_action)

Vensim's VECTOR SELECT, as Python PySD: the elements of expr where sel is non-zero are combined by numerical_action (0 sum of selexpr, 1 product of selexpr, 2 min of selexpr, 3 max of selexpr, 4 mean of sel*expr, 5 product of expr^sel, 6 sum, 7 product, 8 min, 9 max, 10 mean of expr). missing_vals is returned when sel is all zeros. error_action 1 (or 3) raises when sel is all zeros, 2 (or 3) when it has more than one non-zero. sel and expr are broadcast together (e.g. a matrix and a vector).

source
PySD.pysd_not_implemented — Function
pysd_not_implemented(name, args...)

What PySD's translator writes for a Vensim or Stella function it does not translate: an error naming it when the model evaluates it, as Python PySD's not_implemented_function (the translation warns that the model will crash).

Excel and data files

Excel files are cached in memory: one read per file per session.

PySD.pysd_xlsx_read_constant — Function
pysd_xlsx_read_constant(path, sheet, name; transpose=false)

Read a scalar or array constant from an Excel named range or cell reference. The name may end with * to indicate transposition (Vensim convention).

source
pysd_xlsx_read_constant(path, sheet, names::Vector; transpose=false)

Read multiple named ranges from Excel and concatenate them into a single array. Each element of names is either a String (range name to read from Excel) or a Vector{Float64} (literal values to insert directly).

source
PySD.pysd_xlsx_read_series — Function
pysd_xlsx_read_series(path, sheet, x_name, y_names::Vector{String})

Read multiple y-series from Excel sharing the same x-axis. Returns (xs, ys_list) where ys_list is a Vector{Vector{Float64}}.

source
pysd_xlsx_read_series(path, sheet, x_row_or_col, y_cell)

Read x/y series data from Excel for lookups or time-series data. Handles three Vensim reference modes:

  • Row mode: x_row_or_col is a number (row), y_cell is a cell ref
  • Column mode: x_row_or_col is a column letter, y_cell is a cell ref
  • Name mode: both are named ranges

Returns (xs::Vector{Float64}, ys::Vector{Float64}).

source
PySD.pysd_xlsx_build_lookup_dispatch — Function
pysd_xlsx_build_lookup_dispatch(path, sheet, x_name, y_name; n=1, method=:interpolate)

Read a (possibly 2D) lookup or data series from Excel and return a vector of interpolation functions, one per series of the y data. With named ranges the series are the columns (or rows) of the y range; in row or column mode (x_name a row number or a column letter, y_name a cell) they are the n rows (or columns) from y_name. method is a DATA keyword (:interpolate, :hold_backward, :look_forward), as in pysd_build_tab_itp.

source
PySD.pysd_tab_read_series — Function
pysd_tab_read_series(filepath, colname) -> (times, vals)

Read a tab- or comma-separated Vensim output file and return the time series for the column named colname. Matching is case-insensitive and leading/trailing whitespace is ignored.

Accepts Unix, Windows and old Mac (CR only) line endings. Uses only Julia Base functions — no extra packages required.

source
PySD.pysd_build_tab_itp — Function
pysd_build_tab_itp(vals, times, method)

Build a DataInterpolations interpolation object from (times, vals) using the Vensim interpolation method symbol:

  • :interpolate → LinearInterpolation
  • :raw → the value at the data times, NaN in between
  • :hold_backward → ConstantInterpolation (hold previous value)
  • :look_forward → ConstantInterpolation(dir=:right) (next value)

Changing a model's inputs between runs

A generated ODE model's params(; name = value, ...) builds its constants, lookups and data with the given values in place of its own (see PySD's documentation, "Scenarios").

PySD.pysd_input — Function
pysd_input(given, name, default)

The value of the model input name: given[name] when it is there, converted to the kind of value the model has (see below), otherwise default.

  • A constant takes a number, or an array of the constant's own size (a number fills the whole array).
  • A lookup or data series takes anything pysd_lookup accepts.
source
PySD.pysd_lookup — Function
pysd_lookup(value)

A lookup or data series from value, called as the model calls it (f(x), or f(i, x), f(i, j, x) when it is subscripted):

  • a function, used as it is;
  • an interpolation from DataInterpolations.jl (any kind), the same for every element;
  • (x, y): two vectors, interpolated linearly and held constant outside x, as Vensim lookups; the same for every element;
  • (x, Y): a vector and a matrix with one column per element of a one-dimensional subscripted lookup;
  • a number: the same value everywhere.
source
PySD.PySDFunction — Type
PySDFunction{N}(f)

A lookup or data series of a model's parameters, called with N arguments (f(x), f(i, x), ...). Every lookup with N arguments has this type, whatever function it holds, so replacing one (with params) does not change the type of the parameters and the model is not compiled again.

Calls with integer indices and a Float64 go through a FunctionWrapper (FunctionWrappers.jl, as SciML does to avoid recompiling); other argument types (e.g. the numbers of an automatic-differentiation solver) call f directly. The result is a number of the type of the last argument.

source
PySD.pysd_check_inputs — Function
pysd_check_inputs(given, values::NamedTuple)

Throw an error naming the entries of given that are not among the model's constants, lookups and data (values), e.g. a misspelt name.

source
PySD.pysd_check_fixed — Function
pysd_check_fixed(given, fixed::NamedTuple)

Throw an error if given has a new value for a constant whose value was used when the model was translated (fixed: name => what it fixed, e.g. the number of stages of a DELAY FIXED): that needs the model translated again.

source
PySD.pysd_file — Function
pysd_file(dir, file, files)

The path of the input file (as written in the model, relative to the model file's folder dir), or of its replacement in files (a Dict from the name in the model, or its base name, to another path; relative paths are taken from dir).

Fixed delays and samples

What the ODE and MTK backends write for DELAY FIXED and SAMPLE IF TRUE: records at the model's ticks, which a solver stops at (Solvers and the model's ticks).

PySD.PySDTicks — Type
PySDTicks(t₀, Δt)

The records of a run of a translated model: one per fixed delay and sample, by a key (a number or a name), a value per tick. While a solver runs, the tick is the callback's count (a step that ends at the next tick, before the callback has moved to it, is still in the tick before); afterwards it is the last tick at or before the time.

source
PySD.PySDRecord — Type
PySDRecord(ticks, key, n, I...)

Which record a translated equation reads: of ticks, the one of key (a fixed delay, a sample, a RANDOM call's stream), n ticks back (a fixed delay's), element I of an array. One argument instead of several, built with plain numbers when the equation is written: Symbolics registers a method for every combination of plain and symbolic arguments, 3ⁿ of them, so few arguments keep PySD quick to compile.

source
PySD.pysd_fixed_delay — Function
pysd_fixed_delay(ticks, key, n, init, t, I...)

DELAY FIXED: the input recorded n ticks before the tick at t, or, before the first n ticks, init as it was at the first tick (an initial value that is an expression, such as the input itself, is its value at the start); with indices I, that element of it.

source
PySD.pysd_sampled — Function
pysd_sampled(ticks, key, condition, x, init, t, I...)

SAMPLE IF TRUE. At a tick being recorded: x if condition holds, else what it took at the tick before (init at the first). Otherwise, what it took at the tick at t. With indices I, an element: condition, x and init are that element's.

source
PySD.pysd_tick_time — Function
pysd_tick_time(ticks, t)

The time the model sees. While a solver runs, a step that ends at the next tick, before the callback has moved to it (Runge-Kutta's last stage), is still in the tick before: it sees the time just before the next tick, so a switch at a tick (STEP, PULSE, Time >= 2015) changes the rates from that tick on. Otherwise, t. (Back by more than SMALL_VENSIM, which PULSE TRAIN allows for.)

source
PySD.pysd_tick_uniform — Function
pysd_tick_uniform(record, t)
pysd_tick_normal(record, t)
pysd_tick_exponential(record, t)

A standard draw (uniform on [0, 1), normal (0, 1), exponential (1)) for the tick at t, the same for the whole tick: from a generator seeded from the record's key (the RANDOM call's stream), its element and the tick. The same draws in every run, with any solver.

source
PySD.pysd_record! — Function
pysd_record!(ticks, key, x)

Records x for key at the current tick: a fixed delay's input, or a sample's value.

source
PySD.pysd_ticks_callback — Function
pysd_ticks_callback(ticks, record!; t_final)

A SciML callback (with SciMLBase loaded) that makes the solver stop at every tick of ticks up to t_final and calls record!(u, t) there, to record the fixed delays and samples from the state. pysd_free_ticks!(ticks) after the solve lets the records be read by time.

source
PySD.pysd_begin_tick! — Function
pysd_begin_tick!(ticks, t)
pysd_end_tick!(ticks)

The next tick, at the time t: between the two, the model is computed from the state there and its fixed delays and samples recorded (pysd_record!).

source
PySD.pysd_reset_ticks! — Function
pysd_reset_ticks!(ticks)

Forget every record and count the ticks from the start: at the start of a run.

source
PySD.pysd_free_ticks! — Function
pysd_free_ticks!(ticks)

After a solve: the tick is the time's again, to read the records at any time.

PySD.save_results — Function
save_results(sol, state_map, dim_labels, path)

ODE-backend variant. state_map is a vector of (name, index, dim_names) and dim_labels maps each subscript range name to its element labels. Scalar state variables are saved with dimension (time,). Subscripted state variables get one NetCDF dimension per subscript range, named after the range and holding its element labels, in the file order (time, dim_1, ..., dim_n).
