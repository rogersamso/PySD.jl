# PySD.jl

[![CI](https://github.com/rogersamso/PySD.jl/actions/workflows/CI.yml/badge.svg?branch=main)](https://github.com/rogersamso/PySD.jl/actions/workflows/CI.yml)
[![Coverage](https://codecov.io/gh/rogersamso/PySD.jl/graph/badge.svg)](https://codecov.io/gh/rogersamso/PySD.jl)

Runtime companion library for Julia models generated by
[PySD](https://github.com/SDXorg/pysd)'s Julia builder, and a way to write
system dynamics models directly in Julia ([below](#writing-models-in-julia)).

## Installation

From the root of a PySD checkout:

```julia
using Pkg
Pkg.develop(path="pysd/builders/julia/PySD.jl")
```

## What it provides

Generated `.jl` models import this package via `using PySD`. It exports:

### Vensim built-in functions

Symbolic-safe implementations that work inside ModelingToolkit equations:

| Function | Vensim equivalent |
|---|---|
| `pysd_xidz(x, y, z)` | `XIDZ` — safe divide, returns `z` when `y == 0` |
| `pysd_zidz(x, y)` | `ZIDZ` — safe divide, returns `0` when `y == 0` |
| `pysd_pulse(t, start, width)` | `PULSE` |
| `pysd_pulse_train(t, start, interval, width, end)` | `PULSE TRAIN` |
| `pysd_ramp(t, slope, start, end)` | `RAMP` |
| `pysd_step(t, height, step_time)` | `STEP` |
| `pysd_log_base(x, base)` | `LOG` |
| `pysd_logical_and(a, b)` | `:AND:` |
| `pysd_logical_or(a, b)` | `:OR:` |
| `pysd_logical_not(a)` | `:NOT:` |

### Excel data readers

Functions for reading Vensim external data (`GET DIRECT CONSTANTS`,
`GET DIRECT LOOKUPS`, `GET DIRECT DATA`) from Excel files at runtime:

- `pysd_xlsx_read_constant(path, sheet, name; transpose=false)` — read a
  scalar or array constant from a named range or cell reference.
- `pysd_xlsx_read_series(path, sheet, x_ref, y_ref)` — read x/y series
  data for lookups or time-series interpolation. Supports named ranges,
  cell references, and row/column modes.

Excel files are cached in memory (one read per file per session).

### Changing a model's inputs between runs

A generated ODE model's `params(; name = value, ...)` builds its constants,
lookups and data with the given values in place of its own (see PySD's
documentation, "Scenarios").  It uses:

- `pysd_input(given, name, default)` — the given value converted to the
  kind the model has: a number; an array of the constant's size (or a number
  for all of it); for a lookup or data series, anything `pysd_lookup` takes.
- `pysd_lookup(value)` — a lookup from a function, an interpolation from
  DataInterpolations.jl, `(x, y)` vectors (linear, held constant outside
  `x`, as Vensim), `(x, Y)` with one column per element, or a number.
- `PySDFunction` — the type of every lookup and data series in the
  parameters, whatever function it holds, so replacing one does not compile
  the model again (FunctionWrappers.jl for the usual argument types).
- `pysd_check_inputs(given, values)` and `pysd_check_fixed(given, fixed)` —
  errors for names that are not inputs of the model, and for constants whose
  value the translation used (e.g. the number of stages of a DELAY FIXED).
- `pysd_file(dir, file, files)` — an input file or its replacement.

## Writing models in Julia

PySD.jl also has a way to write system dynamics models directly in Julia:
`@equations` for the equations, `Model` to build them, `run_model` to run
them.

```julia
using PySD, Unitful

growth = @equations begin
    @parameters begin
        k = 0.1, [unit = u"1/yr", description = "growth rate"]
    end
    @variables begin
        x(t), [unit = u"kg"]
        g(t), [unit = u"kg/yr"]
    end
    g ~ k * x
    ∂t(x) ~ g              # a stock: its rate of change
    x(t₀) ~ 1              # and its initial value
end

m = Model(growth; time = 0:0.25:100, time_unit = u"yr")
r = run_model(m)
r[:x]                      # x at each saved time
```

- Every name is declared with its unit (`NoUnits` if it has none) and,
  optionally, a description: `@parameters` for what is known before the run,
  `@variables` for the rest, `x(t)` when it changes with time.
- Arrays have DimensionalData dimensions, and an equation can be for a part
  of an array (`x[region = At(:north)] ~ …`, `Not(At(…))` for the rest).
- Smooths, delays, fixed delays, trends, sample-if-true, lookups, and
  constants, lookups and data read from Excel (`excel(path, sheet)`) are built
  in.
- `run_model(m; check_units = true)` checks that every equation's units add
  up before running (`:warn` to only print what doesn't).

### Data from other models or from files

A model can take series from outside it, as Vensim's data variables without
an equation: from another model's run (a regional model fed by a global one),
or from a file of series:

```julia
@parameters begin
    temperature_change = data(parents, :temperature_change), [unit = u"K"]
end
…
damage ~ f(temperature_change(t))
```

`parents` is an input, a tuple of sources given when the model is built and
when it runs; each series comes from the first source that has it, by name,
interpolated linearly between the source's times.  A source is a run
(`run_model(…)`) or a file, `series_file("history.tab")`: a `.csv` or `.tab`
with the times in the first column and a column per series named as in
Vensim (`Temperature change`, `GDP[EU]`), or a row per series, as Python
PySD's `data_files`.

```julia
w  = run_model(world)
eu = run_model(europe; inputs = (; parents = (w,)))
w2 = run_model(world; params = (; k = 0.2))           # another world …
eu2 = run_model(europe; inputs = (; parents = (w2,)))  # … the same Europe, no rebuild
eu3 = run_model(europe; inputs = (; parents = (series_file("world.tab"),)))   # from a file
```

### The equations as LaTeX

```julia
using Latexify                          # loads PySD.jl's LaTeX export
pysd_export_latex(m; filename = "model.tex")
```

writes the equations as they are written: a section per set of equations (a
view of a translated model), stocks as dx/dt, `sum_over` as Σ, `ifelse` as
cases, selections as `x[a]`, and a table of the names with their units and
descriptions.  Without `filename` it returns the LaTeX as a string.

### Running a model again with other values

`Model` compiles the model once.  After that, running it with other parameter
values or other input sheets is fast, and compiles nothing:

```julia
r2 = run_model(m; params = (; k = 0.2))
r3 = run_model(m; inputs = (; scenario = excel("scenarios.xlsx", "High")))
```

This is what a sensitivity analysis needs: many runs with different values.
The one exception is a parameter that sets the structure of an operator,
such as the time of a fixed delay (the number of steps it keeps) or the
order of a smooth.  Changing it needs the model built again, and `run_model`
says so with an error rather than ignoring the new value.

### Derivatives and uncertainties

A run computes in the number type of its parameters, so other kinds of
numbers go through it.  With ForwardDiff.jl, the derivative of any result in
a parameter (for calibration, or to see what a result is most sensitive to);
with Measurements.jl, a parameter's uncertainty carried to every result:

```julia
using ForwardDiff, Measurements
ForwardDiff.derivative(k -> run_model(m; params = (; k))[:x][end], 0.1)
r = run_model(m; params = (; k = 0.1 ± 0.01))
r[:x][end]                 # a value ± its uncertainty
```

The derivative is the exact one of the run, with its Euler steps, not an
estimate from runs with nearby values.

### Loading a model in seconds: models as packages

Building and compiling a large model takes minutes, every time a new Julia
session starts.  To do that only once, keep the model in a package: Julia
saves the built and compiled model when the package is first used, and later
sessions load it ready to run.

A model folder becomes a package with two more files:

```
mymodel/
├── Project.toml        # name = "MyModel", uuid, and PySD in [deps]
├── src/MyModel.jl
├── mymodel.jl          # the model, as before: it ends with Model(…)
└── …                   # its other files, as before
```

```julia
# src/MyModel.jl
module MyModel
using PySD
@precompile_model model = include("../mymodel.jl")
end
```

`@precompile_model` defines `model` (a constant), and builds and runs it once
while Julia precompiles the package, so that all this compiles is saved with
the package.

Then:

```julia
using Pkg; Pkg.develop(path = "mymodel")   # once, in the environment that has PySD.jl
using MyModel                              # later sessions: seconds
r = run_model(MyModel.model; params = (; k = 0.2))
```

- The first `using MyModel` builds and compiles the model and saves it; it
  takes as long as building it without a package, but only once.  For a
  model of 1,867 names: about 8 minutes the first time, then about 8 s to
  load it and 6 s for its first run in every later session (instead of about
  9 minutes in each session).
- When one of the model's files or one of its Excel sheets changes, Julia
  notices at the next `using` and builds it again, once.
- Running with other parameters or inputs works as always and needs no
  rebuild.
- A unit module of the model's own (`@refunit`s) is registered with Unitful
  both when it's defined (`Unitful.register(MyUnits)` after the module) and
  when the package loads it (an `__init__` that does the same), as PySD
  writes it for translated models.

PySD (`translate_to_julia(model; backend = "dsl")`) writes Vensim models in
this form, package files included.

## Running the tests

The tests use the reference models of [SDXorg/test-models](https://github.com/SDXorg/test-models),
included as a git submodule:

```sh
git submodule update --init test/test-models
julia --project -e 'using Pkg; Pkg.test()'
```

Set `PYSD_TEST_MODELS` to use another checkout of test-models (e.g.
`tests/test-models/tests` in a PySD checkout).  Without test-models the
reference tests are skipped with a warning.

## Version compatibility

Generated models embed the PySD.jl version they were translated against.
On load, `check_compat` verifies that the installed PySD.jl is compatible.
A major-version mismatch raises an error; a minor-version mismatch emits a
warning.

## Related work

Writing models in Julia borrows from:

- [ModelingToolkit.jl](https://github.com/SciML/ModelingToolkit.jl):
  `@equations` takes the form of its `@mtkmodel`: `@parameters` and
  `@variables` blocks, `~` for equations, `x(t)` for what changes with time,
  and a unit and description after each declaration.
- [BPTK-Py](https://github.com/transentis/bptk_py): stocks that can't go
  below zero (`nonnegative = true`), parts of a model written once and used
  several times, with their names in the results after the part's
  (`retailer.inventory`, `wholesaler.inventory`), and errors that name the
  algebraic loop (`a → b → a`).
- [DimensionalData.jl](https://github.com/rafaqz/DimensionalData.jl): arrays
  with named dimensions, as xarray's in Python PySD.
- [Unitful.jl](https://github.com/PainterQubits/Unitful.jl): units, and
  checking that each equation's units add up.
- [Vensim](https://vensim.com/) and [PySD](https://github.com/SDXorg/pysd):
  the functions and their behaviour, and the reference outputs the tests
  compare against ([SDXorg/test-models](https://github.com/SDXorg/test-models)).

Also related: [StockFlow.jl](https://github.com/AlgebraicJulia/StockFlow.jl),
stock-and-flow diagrams in Julia, with composition and stratification.
